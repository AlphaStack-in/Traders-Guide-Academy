Technical Architect

SYSTEM & DATA MODEL

Decisions about the shape of the system that only get harder to unwind the longer they sit.

ItemWhy it mattersSeverity
No CI pipeline No .github/workflows exists — nothing builds, lints, type-checks, or runs tests before a change reaches main. Every deploy is a manual act of trust. HIGH
No production observability No error monitoring and no structured logging anywhere in the app. A crashed action or a bad signal parse is invisible until a subscriber or admin happens to notice and say something. HIGH
Single hardcoded admin, dead RBAC schema AdminUser and AdminUserAuditLog tables still exist from a pre-Neon-migration Supabase Auth system, but are entirely unreferenced now — admin-rbac.ts checks a single ADMIN_EMAIL / ADMIN_PASSWORD_HASH env pair instead. No per-admin identity, no real audit trail, and two unused tables sitting in the live schema. MEDIUM
Stock signals misuse the instrument column The instrument enum has no STOCK value, so a stock trade is stored as "NIFTY" and the real symbol only survives via a separately bolted-on stockSymbol column. Works, but the data model doesn't actually describe what happened. MEDIUM
No unique constraint on subscriber email Duplicate accounts are possible at the database layer — uniqueness is only enforced by application-level lookups, not the schema itself. MEDIUM
AdminUpdate.signalId isn't a real foreign key Deleting a signal requires an explicit, separate deleteMany to avoid orphaned update rows — one missed call site anywhere in future code would leak them silently. LOW
Unreachable multi-vendor parser code still bundled Goodwill's parser and the generic auto-detector remain in the codebase from the SignalFlow fork, structurally unreachable from TGA's single-tenant UI — dead weight with no functional risk, but a maintenance tax on anyone reading the parser layer cold. LOW

Product Manager

PRODUCT COMPLETENESS

Gaps between what the product appears to do and what it actually does today.

ItemWhy it mattersSeverity
Payment is entirely manual, off-platform No payment gateway is integrated. The UPI payee ID and manager contact in config are still literal placeholders (TODO@upi) — every collection, reconciliation, and receipt today happens outside the product. HIGH
No self-service plan upgrade or renewal Upgrade/Extend buttons hand off to a WhatsApp conversation rather than completing an in-app transaction — every plan change is a manual, human-in-the-loop process. MEDIUM
Two admin actions look real but do nothing The Registered Members "Announcement" button only shows a toast, and replying to a contact-form message saves the reply internally without ever emailing the person back — an admin could easily believe both actually reached someone. MEDIUM
No admin UI to reset a subscriber's password A code comment claims an admin can reset a subscriber's password from the panel — the button doesn't exist. Today, a reset needs a developer to run a script by hand. MEDIUM
Brand identity still placeholder Logo/favicon, brand colors, and pricing tiers are all marked provisional in client-config.ts — a real go-live needs a deliberate pass to replace every one of them. MEDIUM
Digest, news alerts, and broker connect built but off Weekly digest emails, news alerts, and Dhan broker connect/order placement are all implemented and just switched off — a straightforward product call on if and when to turn each on. LOW

Developer

IMPLEMENTATION

Code-level debt that will slow down or trip up whoever touches these areas next.

ItemWhy it mattersSeverity
Signal parser has zero test coverage The most complex, highest-risk logic in the app — and the source of at least two real bugs found this session alone (misrouted targets, a stale-expiry rollover) — has no automated tests protecting it. Only three test files exist in the whole repo, none of them here. HIGH
No rate limiting or lockout on login Neither subscriber nor admin login throttles repeated password attempts — nothing stands between a real credential set and a brute-force script. HIGH
TODO placeholders shipped in live config client-config.ts and utils.ts carry unresolved TODOs for brand colors, logo path, UPI payee, and production domain — easy to miss without a dedicated go-live checklist pass. MEDIUM
setSubscriberPassword is dead code The server action works and is fully wired to the database, but no UI component calls it anywhere — it's waiting behind the missing admin reset button (see PM). LOW
Admin audit schema is dead weight Same root cause as the Architect item — AdminUser / AdminUserAuditLog mean any future "who did what" admin feature gets rebuilt from scratch, not resumed from what's already there. LOW

QA / Test Engineer

VERIFICATION

What stands between a broken change and a live subscriber seeing it.

ItemWhy it mattersSeverity
No coverage on parser, auth, or signal lifecycle Parsing, login/session handling, and the create/close/delete actions that move real trade data all rely on manual click-through today — there's no automated safety net on the paths that matter most. HIGH
No CI gate at all Nothing today stops an untested, broken change from reaching main — the gate is entirely human review, if that. HIGH
This session's two newest features are untested General Admin Updates and the richer Status-label logic both shipped this session with no test coverage — the latter touches P&L-adjacent display logic worth locking down before it drifts. MEDIUM

DevOps / SRE

OPERATIONS

Operational readiness for the day this stops being a proof of concept.

ItemWhy it mattersSeverity
No CI/CD pipeline Every deploy and every quality gate — lint, type-check, test — is a manual step performed by whoever happens to be pushing. HIGH
No error monitoring or alerting Same gap as the Architect item, from the operations side: there's no on-call signal at all today — an outage is discovered by a person, not a system. HIGH
No rate limiting at the infrastructure layer Nothing in front of the app throttles auth traffic either — this is the same gap as the Developer login item, but there's also no infra-level backstop behind it. HIGH

Compiled from direct codebase inspection (schema, auth, parser, config, test suite, CI config) plus gaps documented while building features earlier in this project's history.

One thing worth restating: SignalFlow is the canonical version and is not live; TGA is a proof-of-concept fork with an India-only subscriber base. None of this is urgent by itself — it's a map for prioritizing before that changes.
